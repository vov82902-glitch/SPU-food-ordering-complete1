# SPU Food — ระบบสั่งอาหารโรงอาหาร

นักศึกษาสั่งอาหารจากร้านในโรงอาหารผ่านเว็บ รับเลขคิว แล้วไปรับอาหาร + จ่ายเงินสดที่ร้าน
ร้านค้าเห็นออเดอร์แบบ real-time ผ่าน Firebase

เทคโนโลยี: HTML + CSS + JavaScript ธรรมดา (ไม่มี framework) + Firebase Firestore (ฐานข้อมูลออนไลน์)

---

## ไฟล์ JavaScript

ทุกไฟล์มี **หัวไฟล์บอกว่าทำอะไร + สารบัญ** อ่านจากบนลงล่างได้เลย

**ไฟล์ที่ทุกหน้าใช้**
| ไฟล์ | ทำอะไร |
|---|---|
| `cloud.js` | เชื่อม Firebase: ดึงข้อมูลมาก่อนเปิดหน้า + ซิงก์แบบ real-time |
| `main.js` | ฟังก์ชันใช้ร่วมกัน: เมนู ออเดอร์ ตะกร้า ผู้ใช้ เสียงแจ้งเตือน |

**กติกาของระบบ** (ตัวเลขตั้งค่าอยู่บนสุดของแต่ละไฟล์)
| ไฟล์ | กติกา |
|---|---|
| `noshow.js` | ลูกค้าไม่มารับ: รอ 15 นาที / ครบ 3 ครั้งพัก 7 วัน / ค้างรับได้ 3 ออเดอร์ |
| `out-of-stock.js` | ของหมด: ทำตามที่ลูกค้าเลือกไว้ตอนสั่ง (เปลี่ยนเป็นของแทนที่เลือกไว้ / ไม่เอาจานนี้) |
| `if-out.js` | หน้าต่าง "ถ้าของหมด จะให้ทำยังไง?" ในตะกร้า |
| `order-timer.js` | ร้านไม่กดรับเกิน 3 นาที -> เตือน + นับถอยหลัง |

**หน้าร้าน** (`admin.html`)
| ไฟล์ | ทำอะไร |
|---|---|
| `admin.js` | ไฟล์หลัก: ล็อกอินร้าน ปุ่มจัดการออเดอร์ เมนู ตั้งค่า |
| `admin-board.js` | กระดานออเดอร์ 3 คอลัมน์ (มือถือเป็นแท็บ) |
| `admin-options.js` | แก้ตัวเลือกของเมนู |
| `admin-stock.js` | หน้าต่าง "ของหมด" |
| `admin-cancel.js` | หน้าต่างยกเลิกออเดอร์ (ปุ่มเลือกเหตุผล) |

## ข้อมูลเก็บที่ไหน

| ข้อมูล | เก็บที่ | เหตุผล |
|---|---|---|
| เมนู ร้าน ออเดอร์ บัญชีนักศึกษา | Firebase (ออนไลน์) | ทุกเครื่องต้องเห็นข้อมูลชุดเดียวกัน |
| ใครล็อกอินอยู่ ตะกร้า | localStorage (ในเครื่อง) | เป็นของแต่ละคน ไม่ต้องแชร์ |

`cloud.js` คัดลอกข้อมูลจาก Firebase มาไว้ใน localStorage ก่อนเปิดหน้า
โค้ดหน้าเว็บจึงอ่านข้อมูลด้วย `loadOrders()` / `loadStudents()` แบบธรรมดาได้เลย
และตอนบันทึก (`saveOrders()` ฯลฯ) จะส่งขึ้น Firebase ให้เอง

## สถานะของออเดอร์

```
new (สั่งแล้ว) -> cooking (กำลังทำ) -> ready (พร้อมรับ) -> done (รับแล้ว + จ่ายเงินแล้ว)
      |                 |                    |
      +-> cancelled     +-> cancelled        +-> noshow (ไม่มารับเกิน 15 นาที)
```

## ข้อจำกัด / สิ่งที่จะพัฒนาต่อ

- **ความปลอดภัย**: ฐานข้อมูลยังเป็น test mode และรหัสผ่านแฮชแบบง่าย
  ถ้าใช้จริงควรเปลี่ยนไปใช้ Firebase Authentication + Security Rules
- **จ่ายเงิน**: รับเงินสดที่ร้านอย่างเดียว ถ้าจะเพิ่ม QR ควรใช้ payment gateway
  ที่ตรวจสลิปและคืนเงินอัตโนมัติได้
- **เลขคิว**: ถ้าลูกค้า 2 คนสั่งร้านเดียวกันในวินาทีเดียวกันพอดี อาจได้เลขคิวซ้ำ
